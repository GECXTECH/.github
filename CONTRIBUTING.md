# Contributing to GECX Tech

Thanks for your interest in contributing. Here is a quick guide.

## Before You Start

- Check if an existing issue already covers your idea
- For major changes, open an issue first to discuss the approach
- For security concerns, see our SECURITY.md

## Development Workflow

1. Fork the repository
2. Create a feature branch (git checkout -b feature/my-change)
3. Make your changes with clear commit messages
4. Push to your fork and open a pull request

## Pull Request Checklist

- [ ] One change per PR
- [ ] Code follows the existing style
- [ ] New features include tests where applicable
- [ ] Documentation updated if behavior changed

## Code of Conduct

This project follows our CODE_OF_CONDUCT.md. Be respectful and inclusive.
